# TimeLapser v1.0.46

Two recording/export bug fixes.

## Fixed

- **Export duration now matches "Timelapse length (s)".** Setting a target length (for example, 20 s) for an MP4/WebM/MOV export now produces a clip of that exact duration. Previously the concat demuxer ignored the per-frame timing and exports came out a fraction of a second (or otherwise unrelated to the requested length). The fix passes the effective output FPS as the input rate to FFmpeg so each frame gets `1/fps` duration. Affects all video exports; GIF export was not affected.
- **Recording no longer stalls at 0 frames on Windows with `NoDefaultCurrentDirectoryInExePath` enabled.** The bundled screenshot helper (`screenshot-desktop`) ships a self-compiling `.bat` that invokes its compiled `.exe` by bare name. On Windows installs where the current directory is not in the executable search path (the default on Windows 10/11), every capture tick failed with `'screenCapture_1.3.2.exe' is not recognized…` and no frames were written. The installer now patches the helper to invoke the compiled `.exe` via its absolute path. Existing users who hit this should now see frames accumulate immediately after pressing Record.
